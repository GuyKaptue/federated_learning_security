# SYN-IDS-v1 (synthetic benchmark)

**SYN-IDS-v1 is completely synthetic despite its name.** It is not real intrusion-detection data, it is not patient data, and it was designed only as a benchmark for federated-learning experimentation.

| Parameter | Value |
|---|---|
| Generator | `sklearn.datasets.make_classification` (module `federated_learning.synthetic_data.generators.syn_ids_v1`) |
| Samples / features | 12000 / 40 (default; configurable) |
| Task | binary classification |
| Class weights | 0.6 / 0.4 (realised positive rate 0.4022 after 2% label noise) |
| Clusters per class | 3 |
| Class separation / label noise | 0.9 / 0.02 |
| Split | stratified 70/30; standardisation fitted on TRAIN |
| Seed | 0 by default (`configs/synthetic_data.yaml`) |

## Used for
Federated-learning benchmarks, cryptographic overhead evaluation, secure-aggregation experiments, adversarial attack simulations, defence evaluation, scalability experiments and hyper-parameter optimisation.

## Generation, validation and quality pipeline
```bash
PYTHONPATH=src python -m federated_learning.synthetic_data.pipelines --seed 0
```
Writes `data/synthetic/syn_ids_v1/syn_ids_v1_seed<S>.npz`, `data/synthetic/validation/…json` (spec checks, quality report, train/test PSI, SHA-256 of the arrays) and `data/synthetic/metadata/…json` (dataset card). The generated files are fully synthetic and are therefore committed for seeds 0 and 1; they are byte-reproducible from the seed.

Validators check shape, binary labels, finiteness, class ratio (tolerance 0.03 because of label noise) and non-constant features. Quality metrics: duplicate rows, maximum absolute feature correlation, and the held-out AUC of a logistic-regression probe (a learnability indicator, not a claim about realism). Drift analysis (PSI, Kolmogorov–Smirnov) compares train/test or clients.

## Client partitioning
`data_partitioning.partition(...)`: IID, stratified, Dirichlet label skew, label shards, quantity skew; `simulate_missing` adds MCAR/MAR/MNAR missingness.

## Ethical considerations and licence
No real person or organisation is represented. Generated data carry no licence restrictions. Never present results on SYN-IDS-v1 as evidence about real networks or patients.

## Clarifications that apply to every dataset in this project
* **SYN-IDS-v1 is completely synthetic despite its name.** It is generated by scikit-learn `make_classification`; it is not real intrusion-detection data and not patient data.
* **No real hospital data is used and no patient-identifiable data exists anywhere in the project.** The public healthcare tables are de-identified research datasets published by their owners.
* **All federated-learning clients are simulated locally** in one process (virtual clients). The four natural "sites" of the heart-disease data are four 1980s research cohorts, not live hospital federations.
* **Raw source datasets are not redistributed** with the repository. They are downloaded on first use into `data/raw/<dataset>/` and refused if their SHA-256 differs from the pinned value.
* **Some datasets are fetched from public third-party mirrors.** The licence of the original dataset is documented where it could be read on the original source page; the licence of the mirror itself was *not* verified.
* **CIC-IDS-2017 was not available and is not used** in the final implementation. Results on SYN-IDS-v1 must never be compared numerically with CIC-IDS-2017 results.
* **No credentialed clinical repository (e.g. PhysioNet MIMIC-IV, eICU) was available, so none is used** in the paper or in the code. No electronic-health-record data are present anywhere in this project.
